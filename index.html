GKE system metrics can be sent to Cloud Monitoring. Google Cloud Managed Service for Prometheus can also collect Prometheus metrics from workloads and store them in Monarch.

2. What is Monarch?

Monarch is Google's large-scale time-series monitoring/storage system used by Cloud Monitoring.

SRE abstraction: 
Metric producer → metric ingestion → Monarch → Cloud Monitoring query/API → monitoring/automation system

A Python application normally does not connect directly to an internal Monarch server. It uses supported interfaces such as the Cloud Monitoring API or PromQL/Prometheus interfaces.

8. Python: query a GKE metric

from google.cloud import monitoring_v3
from google.protobuf.timestamp_pb2 import Timestamp

PROJECT_ID = "my-gcp-project"

client = monitoring_v3.MetricServiceClient()

now = Timestamp()
now.GetCurrentTime()

start = Timestamp()
start.FromSeconds(now.seconds - 300)

interval = monitoring_v3.TimeInterval(
    {
        "end_time": now,
        "start_time": start,
    }
)

filter_string = """
metric.type = "kubernetes.io/container/cpu/limit_utilization"
"""

results = client.list_time_series(
    request={
        "name": f"projects/{PROJECT_ID}",
        "filter": filter_string,
        "interval": interval,
        "view": monitoring_v3.ListTimeSeriesRequest.TimeSeriesView.FULL,
    }
)

for series in results:
    print("Metric:", series.metric.type)
    print("Resource:", series.resource.type)

    for point in series.points:
        print(
            "timestamp:",
            point.interval.end_time,
            "value:",
            point.value.double_value,
        )

9. Querying by GKE resource labels

You normally don't want all containers in a production project.

filter_string = """
metric.type = "kubernetes.io/container/cpu/limit_utilization"
resource.type = "k8s_container"
resource.labels.cluster_name = "prod-gke"
resource.labels.namespace_name = "payments"
"""

results = client.list_time_series(
    request={
        "name": f"projects/{PROJECT_ID}",
        "filter": filter_string,
        "interval": interval,
        "view": monitoring_v3.ListTimeSeriesRequest.TimeSeriesView.FULL,
    }
)

The exact resource/label names depend on the metric and resource type. Verify them against the current metric descriptor before implementing production queries.

11. PromQL option

If workload metrics are collected through Managed Service for Prometheus, PromQL is another query path. Cloud Monitoring supports PromQL-style queries for Cloud Monitoring and Prometheus metrics.

metric_name{pod_name="payment-api"}

This lets an Automon service use a Prometheus-style query model while the underlying monitoring data is served by Google's monitoring backend.

14. Example production flow

  1. GKE: the payment-api container runs and produces monitoring data.
  2. Collection: GKE/Prometheus monitoring infrastructure collects the relevant metric.
  3. Ingestion: the metric is written into Cloud Monitoring's monitoring backend.
  4. Monarch: Monarch stores and serves the time-series data.
  5. Automon query: Automon asks Cloud Monitoring for CPU utilization for a selected cluster/namespace/service and time range.
  6. Evaluation: Automon applies the configured rule.
  7. Enrichment: Automon can add cluster, namespace, pod, container, deployment, node and incident context.
  8. Action: Automon can create an incident, send a notification, open a ticket, update a dashboard, or trigger an approved remediation.

16. What to verify in your internal Automon implementation

1. Automon repository
2. Automon API/service endpoint
3. Authentication mechanism
4. GCP project / metrics scope
5. GKE cluster naming convention
6. Metric names being monitored
7. Resource labels used by Automon
8. Query interval
9. Polling/scheduling mechanism
10. Alert thresholds
11. Incident destination
12. Remediation actions

Especially verify whether your internal Automon already has a wrapper such as:

from automon import MonarchClient

or:

from automon.monitoring import query_metric

If such an internal wrapper exists, use it instead of calling the Google client directly throughout the application.
